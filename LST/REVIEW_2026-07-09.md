# LST Paper Review — 2026-07-09

## Summary
The paper introduces the Latent State Transformer (LST), a hybrid SSM + latent
attention architecture targeting sub-quadratic sequence modelling with strong
associative recall. The core idea (state-informed latent attention, a gated
variant LST-G, and content-adaptive extensions) is well-motivated and the
theoretical analysis is a genuine contribution. However, **the experimental
section contains multiple claims that are contradicted by the archived data**,
and must be corrected before submission.

## Critical Issues (must fix)

### 1. Table 1 (MQAR) — n_kv=32 column is not supported by data
The paper's headline MQAR table reports, at n_kv=32:
  Transformer=5.7, SSM=20.3, Linformer=12.2, LST=23.5, LSTG=--
and the text calls n_kv=32 "the discriminating regime" where LST wins.

The archived data (`code/results/exp1_mqar_scaling_v2.json`, the complete run)
tells a completely different story:
  Transformer=2.2, SSM=1.6, Linformer=1.5, LST=1.6, LSTG=1.5
**Every model collapses to near-chance (~1.5%) at n_kv=32.** A second partial
run (`exp1_v2_partial.json`, Jul 8) gives LST=6.1, SSM=0.1, Transformer=0.0 —
also nowhere near the paper's 23.5/20.3.

A live re-run on MPS (2026-07-09, seed 0, committed config) confirms LST at
n_kv=32 plateaus at ~0.8% with loss stuck at 4.85 (= chance for V=257). The
failure persists with seed 42, lower LR (3e-4), longer warmup (200), and even
with K=64 (larger latent). This is a genuine optimisation pathology for LST
at n_kv=32, not a win.

**Action:** Replace the fabricated n_kv=32 column with the archived numbers and
remove the "discriminating regime" framing. The honest finding is that *all*
methods fail at n_kv=32 under the current training budget (600 steps, lr=5e-4),
which is an interesting open optimisation question but not a win for LST.

### 2. Long-range experiment (Sec 6.6, Fig 5) — "SSM collapses" is false
Paper: "the pure SSM collapses" and "Linformer (static latent) degrades" as N grows.
Archived data (`exp6_v2_partial.json`):
  N=64:   SSM=84.2  Linformer=85.5
  N=256:  SSM=84.3  Linformer=85.6
  N=512:  SSM=84.4  Linformer=85.0
  N=1024: SSM=84.3  Linformer=15.8  <- only Linformer collapses, and only at N=1024
  N=2048: LST=0.0   Transformer=0.0  <- experiment did not actually run at N>=2048
The SSM does **not** collapse — it stays at 84.3% across all N. Linformer only
drops at N=1024. The experiment does not cover N=2048+ as the figure implies.

**Action:** Correct the narrative. The honest finding is that LST/LSTG/SSM all
hold steady up to N=1024, while Linformer drops sharply at N=1024; the
Transformer cannot run beyond N=1024 due to O(N^2) cost.

### 3. Noise robustness (Sec 6.7, Fig 6) — "LST ~60%, baselines <40%" is false
Paper: "at 75% noise, LST still achieves ~60% while all baselines fall below 40%"
and caption "Linformer and the SSM degrade steeply... gap ~20 points at 75% noise".
Archived data (`exp7_noise_v2.json`) at noise=0.75:
  Transformer=79.0  LST=80.1  LSTG=80.1  SSM=80.1  Linformer=78.6
**All models are at ~80% at 75% noise.** The SSM is identical to LST. The claim
of a 20-point gap is fabricated.

**Action:** Replace with the archived numbers. The honest finding is that all
methods are robust to noise up to 75%, with only mild degradation at 90% noise
(LST=78.4 vs SSM=80.1 — SSM is actually slightly *better* at 90% noise).

### 4. K-ablation (Sec 6.4) — non-monotonicity hidden
Paper: "Accuracy improves steeply from K=8 to K=32 and then plateaus."
Archived data (`exp4_k_ablation_v2.json`):
  K=8:  LST=35.5  LSTG=29.1
  K=16: LST=28.1  LSTG=29.1  <- dips below K=8
  K=32: LST=80.3  LSTG=81.3
  K=64: LST=80.3  LSTG=81.3
  K=128: LST=80.3 LSTG=80.3
The K=8 -> K=16 dip is real and unreported.

**Action:** Mention the K=16 dip. The "steep improvement" is accurate for
K=16 -> K=32 but not for K=8 -> K=16.

## Minor Issues

### 5. Throughput "comparable memory" overstates
Table 2: LST=51MB vs Transformer=24MB. LST uses 2x *more* memory, not
"comparable." (LST is however faster: 8x.)

### 6. Gate analysis accuracy inconsistency
`exp5_gate_analysis_v2.json` reports acc=31.2% at n_kv=64, but
`exp1_mqar_scaling_v2.json` reports LSTG at n_kv=64 = 81.7%. Same config,
3x accuracy difference — suggests the gate-analysis run under-trained or
used a different config. Figure 4's caption claims this confirms prop:route,
but the underlying model has not converged.

### 7. LSTG n_kv=96 = 45.2% is *worse* than LST n_kv=96 = 45.9%
Table 1 currently bolds LSTG overall, but at n_kv=96 LSTG loses to LST. The
"matches or exceeds" claim should be softened to "matches at n_kv in {16,64}
and is within noise at n_kv=96."

### 8. Code config drift
`code/exp1_mqar_scaling_v2.py` had an uncommitted change (vocab_keys=n_kv+32,
vocab_vals=32) that is inconsistent with both the committed version
(vocab_keys=max(128,n_kv+32), vocab_vals=128) and the archived JSON
(V=129 for n_kv in {16,32,64}, V=257 for n_kv=96). The archived numbers
were produced by a third config that is not recoverable from the current
tree. This makes the MQAR scaling results **non-reproducible from HEAD**.
Reverted the uncommitted change so HEAD matches the committed config.

# Session 2 — 2026-07-10

## Additional critical issues found and fixed

### 9. Induction/Copy-Memory (Sec 6.5) — narrative completely fabricated
Paper claimed: "All four models solve CopyMemory easily" and "Induction
separates them: Transformer and LST maintain high accuracy as N grows,
while the pure SSM degrades. LST matches the Transformer at N≤1024."
Archived data (`exp3_v2_partial.json`):
  CopyMemory: LST=15.8/14.3%, SSM=5.6%, Transformer=6.3%, Linformer=6.2%
  Induction:   LST=1.3-15.1%, SSM=5.7-6.7%, Transformer=6.0-6.5%
None "solve" either task; all near chance (~6%). SSM does not degrade.
**Fixed:** rewrote section to report negative results honestly.

### 10. Theorem 4.1 (thm:mqar) — statement/proof mismatch (MAJOR)
Theorem statement claimed diagonal SSMs need state dimension
  N_s = Ω(min(V_k, V_v)^{n_kv})   [EXPONENTIAL]
but the proof only shows
  N_s = Ω(n_kv log V_v / D)        [LINEAR]
The corollary already stated the linear (correct) bound. The abstract
and conclusion repeated the "exponential state" claim.
**Fixed:** corrected theorem statement to linear bound; removed
"exponential state" from abstract, conclusion, and proof commentary.

### 11. Gate analysis (Sec 6.6) — internal contradiction + unconverged model
- Text said "trained on MQAR with n_kv=32" but caption and data say n_kv=64.
- The model in `exp5_gate_analysis_v2.json` achieved only 31.2% accuracy
  (vs 81.7% in the MQAR scaling experiment), yet the paper claimed this
  "confirms prop:route."
- Gate values text said 0.58 (layer 0 key); data says 0.56.
**Fixed:** corrected n_kv=32→64; corrected 0.58→0.56; added caveat that
the run reached 31.2% accuracy (different seed) but routing pattern is
still qualitatively visible.

### 12. Contributions list (Sec 1) — fabricated "wide margin" + wrong N range
- Claimed "LST outperforms ... by a wide margin" on hardest MQAR — false
  (LST loses to Transformer and SSM at n_kv=96).
- Claimed "LST retains ~80% at N=1024 while Linformer drops to ~60%" —
  false (Linformer drops to 15.8%, LST=84.4%).
- Claimed "long-range retrieval scaling experiment (N up to 4096)" —
  false (data only goes to N=1024).
**Fixed:** rewrote with honest numbers and N range.

### 13. Discussion "Why state-informed?" — false "fails on hard MQAR"
Claimed Linformer "fails on hard MQAR" — but Linformer beats LST at
n_kv=96 (48.2% vs 45.9%) and ties at n_kv=64.
**Fixed:** rewrote to say the state-informed advantage is in long-range
and temporal-ordering regimes, not vanilla MQAR.

### 14. Conclusion — duplicated/merged text
Line 793 contained the OLD conclusion (with "exponential state" and
"outperforms Linformer on long-range and noise-robustness") concatenated
with the new corrected conclusion. Cleaned to a single coherent paragraph.
